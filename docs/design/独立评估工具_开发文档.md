# 独立多模型 VLM 评估打分工具 —— 开发文档

把一批模型在航空评估集（选择/判断/开放三类 TSV）上的**推理预测**，离线打分并产出**多模型对比报告**。
**不依赖 VLMEvalKit 的 run.py 评估流程**：推理仍由 VLMEvalKit 完成（产出预测文件），本工具只读这些预测文件做判分与聚合，可反复跑、不重复推理。

---

## 0. 为什么要独立工具（背景）

- 官方 `run.py` 的评估范式是"单模型逐条判分"，`evaluate(eval_file)` 一次只拿一个模型的预测，**做不了成对（A vs B）比较**，也不方便做长度去偏和多模型横向对比。
- 我们要的三件事——**看图裁判**、**长度控制（去除啰嗦偏差）**、**成对/多模型对比**——其中后两者跳出了官方单模型钩子，必须独立脚本。
- 但**推理很贵、判分相对便宜**：所以推理继续用 VLMEvalKit 跑（每个模型一次），本工具**复用它产出的预测文件**，只做判分。判分结果也要缓存，加模型/重跑不重判。

### 评估维度（贯穿全程）
- **能力 capability（主，6 类）**：P1 文本/标号读取、P2 数值/坐标读取、P3 零件识别/定位、R1 结构关系推理、R2 数值/趋势推理、R3 领域知识推理。
- **内容类型 content_type（次，7 类）**：数据图表、坐标曲线、结构图、零件图、流程图、表格、其他。
- TSV 里：`category`=capability，`l2-category`=content_type。

### 模型角色
- **被测模型**：多个（如基模 + SFT 各轮 checkpoint），本工具横向对比它们。
- **裁判模型**：`qwen3.6-27b`（多模态），OpenAI 兼容端点 `http://192.168.48.7:18180/v1/chat/completions`，key `sk-local`。只用于开放题判分，**不参与被测**。

## 1. 输入

### 1.1 真值数据（TSV，三个，已有）
`aero_mcq.tsv`（单选）、`aero_judge.tsv`（判断，已编码成 2 选项 MCQ：A=正确/B=错误）、`aero_vqa.tsv`（开放）。
列：`index`、`image`(base64)、`question`、`A/B/C/D`(选择/判断有，开放无)、`answer`(选择/判断是字母，开放是参考描述)、`category`、`l2-category`、`source_id`。
**图片就在 TSV 里（base64），裁判看图直接从这里按 index 取。**

### 1.2 各模型的推理预测文件（复用 VLMEvalKit 产物）
每个被测模型对每个数据集，VLMEvalKit 跑完会在 `work_dir/{model_name}/` 下产出预测文件
（通常 `{model_name}_{dataset}.xlsx`）。列至少含：`index`、`question`、`prediction`（模型输出）、
以及多半带过来的 `answer`/`category`/`l2-category`。
**本工具读这些文件拿 `prediction`，不重新推理。**

### 1.3 模型清单配置（核心）
配置一个模型列表，每个模型给出名字 + 它三个数据集的预测文件路径（显式路径，或给 `work_dir`+命名规则自动拼）。例：
```python
MODELS = [
  {"name": "base",    "mcq": ".../base/base_aero_mcq.xlsx",    "judge": ".../base/base_aero_judge.xlsx",    "vqa": ".../base/base_aero_vqa.xlsx"},
  {"name": "sft_ep1", "mcq": ".../sft_ep1/...mcq.xlsx",        "judge": "...",                              "vqa": "..."},
  # ... 任意多个
]
BASELINE_MODEL = "base"   # 成对比较/对比基准
```
- 支持任意 N 个模型（2~几十个都行）。
- 某模型缺某数据集的预测文件 → 跳过该数据集、警告，不崩。

## 2. 总体架构与数据流

```
TSV(真值+图)  ─┐
                ├─► 加载 & 按 index 建索引（image_map / gt_map：answer, category, l2-category, source_id）
预测文件(每模型) ┘        │
                          ▼
        ┌──────────── 判分（按题型分流）─────────────┐
        │ MCQ/判断：选项字母抽取 + 精确匹配（即时，无需裁判）│
        │ 开放-点式：看图 LLM 裁判 → hit(0/1)+理由（并发+缓存）│
        │ 开放-成对：看图 LLM 裁判 A/B/平局（位置对调，并发+缓存）│
        └──────────────────────────────────────────────┘
                          │
                          ▼
        聚合：每模型 by能力/内容类型/能力×内容类型交叉；长度控制分；
              多模型对比表；成对胜负矩阵；bootstrap 置信区间
                          │
                          ▼
        产出：逐条明细(每模型) + 对比汇总(CSV/JSON) + 成对结果
```

**判分缓存（关键，"生成一次不用等待"）**：
- 点式裁判结果按 `(model, dataset, index)` 缓存到 JSONL；成对结果按 `(model_A, model_B, index, 方向)` 缓存。
- 重跑 / 加模型时，已判过的直接读缓存，只判新增；中断可续。

## 3. 判分规格

### 3.1 单选（aero_mcq）/ 判断（aero_judge）：选项字母 + 精确匹配
被测模型输出是自由文本（可能"答案是A""A. 滑油泵""我选A因为…"），要**鲁棒地抽出它选的字母**再和真值 `answer` 比。抽取优先级：
1. 匹配明确的"答案/选 X""答案是 X""**X**"等模式里的单个 A–D（判断题只有 A/B）。
2. 找文本中**独立出现**的单个选项字母（前后是边界，避免把单词里的字母误判）。
3. 若没字母但**复述了某个选项的文本** → 用选项文本反查字母（把 prediction 和 A/B/C/D 选项文本做匹配，命中唯一一个就取那个字母）。
4. 出现多个不同字母 → 取第一个，并标 `ambiguous=true`。
5. 完全抽不出 → 记为未作答（判错），标 `no_answer=true`。
- 命中即 `hit=1`，否则 0。**这一步即时、不用裁判、不用并发。**
- 选项抽取建议**可选 LLM 兜底**开关：抽不出时调裁判模型只"抽取所选字母"（不判对错），默认关（省调用），需要时开。

### 3.2 开放-点式（aero_vqa）：看图 LLM 裁判（已有现成逻辑可复用）
- **裁判看图**：发 图(base64) + 描述任务 + 参考描述 + 模型回答，二值判 `correct`。
- 评分标准（长度中性、看图为准、扣编造与空泛）见已实现文件 `aero_vqa_dataset.py` 里的 `VQA_JUDGE_PROMPT`，可直接搬。
- **可直接复用 `aero_vqa_dataset.py` 中的**：`_judge_call`(已支持传图)、`_parse_judge`、并发评分 `score_dataframe`、以及辅助指标 BLEU-1/2、ROUGE-L、pred_len。这些不用重写。
- 产出每条：`hit`、`judge_reason`、`pred_len` + 辅助指标。

### 3.3 开放-成对（aero_vqa，A vs B）：看图裁判判优劣
- 对**同一道题**的两个模型回答 A、B：发 图 + 问题 + 参考 + 回答A + 回答B，裁判判 `A更好 / B更好 / 平局`。
- **必须消位置偏差**：同一对跑两个方向（A在前、B在前各一次），按规则合并：
  - 两个方向都判同一个赢 → 该模型赢；
  - 两方向不一致（各赢一次，或都判平）→ 记**平局**。
- **必须允许平局**：裁判要能输出 tie，别强行分胜负。
- 多模型怎么配对（可配）：
  - 默认：**每个模型 vs 基准模型（BASELINE_MODEL）**，输出各模型相对基准的胜/平/负。
  - 可选：**全配对 round-robin** → 用 Bradley-Terry / Elo 排出名次（像 Chatbot Arena）。
- 成对裁判提示词另写一版（输出 `{"winner": "A"/"B"/"tie", "reason": "..."}`），同样**长度中性、看图为准**。

## 4. 长度控制（去除"啰嗦红利"）

LLM 裁判有公认的长度偏差（偏好长回答），需对 `pred_len` 去偏。做法（AlpacaEval-LC 思路）：

### 4.1 点式（绝对分）
- 收集逐条 `(model, hit, pred_len)`。
- 拟合**逻辑回归**：`hit ~ C(model) + pred_len`（`pred_len` 作协变量，model 作因子，基准=BASELINE_MODEL）。
- **长度控制分** = 在**固定参考长度**（取全体 `pred_len` 均值）下，预测各模型的 P(hit)。
- 报告时**原始准确率 + 长度控制准确率并列**。

### 4.2 成对（胜率）
- 逻辑回归：`A胜 ~ (len_A - len_B)`（+ 模型对的因子），在 **长度差=0** 处评估 → 长度控制胜率。

### 4.3 边界
- `pred_len` 几乎无方差、或逻辑回归完美分离 → 回退并告警，仍给原始分。
- 每个 cell 样本太少 → 长度控制不稳，标注样本数、原始分照给。
- 用 `statsmodels`（Logit）实现；缺库则降级为"按长度分箱后比较"的近似，并说明。

## 5. 聚合与报告

### 5.1 每个模型（三类数据集分开）
- 总分：MCQ 准确率、判断准确率、开放 hit 率（+ 长度控制分）。
- 按 `capability` 分项；按 `content_type` 分项。
- **能力 × 内容类型交叉表**（pivot，值=准确率/hit率）；**同时给每格样本数**（稀疏格才看得出可信度）。

### 5.2 多模型对比（核心诉求）
- 一张**模型 × 指标**总表：行=各模型（base、sft 各轮…），列=各数据集总分 + 各能力 + 各内容类型，方便横向看谁强谁弱。
- 开放题额外给**长度控制分**列，和原始分并排。
- 成对：**各模型 vs 基准**的 胜/平/负 率表（按能力、内容类型再拆）；若开 round-robin，给名次表。

### 5.3 置信区间（你没提，但必须有）
你最关心"几个点的差是不是噪声"。对每个指标做 **bootstrap**：对条目有放回重采样 B 次（如 1000），重算指标，给 2.5/97.5 分位的区间。
- 报告里每个分数都带 CI；**两个模型 CI 重叠 = 差异不显著**，别当成"提升"。
- 成对胜率同样给 CI（看胜率是否显著偏离 50%）。

### 5.4 逐条明细（审裁判用）
每模型每数据集导一份明细：`index, source_id, capability, content_type, question, answer/参考, prediction, hit/抽取字母, judge_reason, pred_len`。
用来人工抽查裁判是否公平（基模被判错是否因"编造"、SFT 被判错是否因"真模糊"）。

## 6. 并发、缓存、续跑

- **并发**：裁判调用（点式 + 成对）是耗时主力，用线程池，`MAX_WORKERS` 可配（本地端点可拉到 16/32/64）。MCQ/判断的字母抽取即时、不需并发。
- **缓存/续跑**：
  - 点式：`{(model,dataset,index): {hit,reason}}` → JSONL，实时落盘，重跑跳过已判。
  - 成对：`{(model_A,model_B,index,方向): {winner,reason}}` → JSONL。
  - 加新模型只判新增；裁判 `temperature=0` 保证可复现，配合缓存彻底"判一次不再等"。
- **复用推理**：被测模型的预测文件只读不改；本工具从不重新推理。

## 9. 边界与易错点（务必覆盖）

1. **预测文件列名/版本差异**：`prediction` 可能叫别的；`index` 可能是 int/str。做列名探测 + index 统一成字符串再 join。
2. **预测缺失/为空**：某模型某条没预测 → 记判错并标 `missing=true`，不崩；报告缺失条数。
3. **index 对齐**：预测与 TSV 按 index 内连接；落单的（预测多出来或 TSV 缺）单独列出，不静默丢。
4. **图片来源**：一律从真值 TSV 按 index 取 base64（预测文件不一定带图）；图只加载一次进 `image_map`，多模型/成对复用，别重复解码。
5. **MCQ 选项抽取鲁棒性**（见 3.1）：自由文本里抽字母最容易错，按优先级来；抽不出标 `no_answer`，别默认判对。
6. **判断题方向**：真值 A=正确/B=错误；模型可能直接答"正确/对" → 抽取时把"正确/对/是"→A、"错误/错/否"→B 也认。
7. **裁判 JSON 解析失败**：重试→仍失败记 0 并标 `[judge_error]`，报失败数；别让一条坏 JSON 拖垮整轮。
8. **成对位置偏差**：必须两方向都跑 + 合并规则（5 节/3.3）；不可只跑一个方向。
9. **成对平局**：允许且尊重 tie，别强分胜负。
10. **裁判自我偏好**：裁判是 Qwen 系，被测多半也是 Qwen 系 → 自我偏好对两边影响相近，差异性影响小；报告里注明这一点，结论别过度解读。
11. **长度控制退化**：方差不足/完美分离 → 回退+告警，仍给原始分（4.3）。
12. **交叉表稀疏格**：无/极少样本的格给 NaN/空 + 标样本数，别把 1/1=100% 当强信号。
13. **不同题型别混算**：MCQ/判断是 0/1 准确率，开放点式是裁判 hit 率，成对是胜率——**尺度不同，分开报、标清楚**，不要平均成一个总分。
14. **并发稳定性**：端点高并发可能偶发失败 → 重试（可加退避）；`MAX_WORKERS` 可调。
15. **大 base64 内存**：图只进一份 `image_map`；明细落盘时**不要**把 base64 写进 xlsx（太大），明细里放 index/source_id 即可，要看图回 TSV 查。
16. **可复现**：裁判 `temperature=0` + 缓存；bootstrap 固定随机种子；所有配置集中、不写死。
17. **任意模型数**：2 个到几十个都要正常；只评 1 个模型时跳过成对、只出绝对分。
18. **参考答案偏弱**：开放题参考是自动生成、可能粗/含糊 → 看图裁判以图为准来兜（已设计），报告里注明参考仅供参照、非唯一标准。

## 12. 验收标准
- 给定 N 个模型的预测文件，一条命令产出多模型对比报告，**不重新推理**。
- 重跑/加模型，裁判判分走缓存、只判新增（明显变快）。
- 开放题给出：原始 hit 率 + 长度控制分 + 各模型 vs 基准的成对胜率，且**都带 bootstrap 置信区间**。
- 能产出每模型的能力×内容类型交叉表（带样本数），和多模型横向对比总表。
- 逐条明细可导出供人工审裁判。
- MCQ/判断的选项抽取在自由文本预测上鲁棒（含复述选项文本、答"对/错"等情形）。

## 13. 方法论须知（写给使用者，别误用）
- **公平 ≠ 让 SFT 赢**：这套设计是为去掉长度等混淆、让真实差异显出来。若公平评估后开放题仍是 base≈SFT，那大概率是真相——去看客观题(MCQ/判断)里 SFT 的提升，别在开放题上反复调裁判逼出"提升"。
- **小差距先看 CI**：CI 重叠就是没差异，别当提升。
- **三类分开看**：开放题考"看图详述"，客观题考"精确读图"，SFT 的价值可能只在后者，分开看才完整。
- **长度控制分 vs 原始分并看**：若原始分 base 高、长度控制分追平/反超，就坐实了"基模靠啰嗦刷分"。
