前四行来自既有运行的原始 `acceptance_score.csv` 或 `score_summary.csv`；后三行来自 2026-10-09 全量运行。不同数据集和评分器的数值不能当同一种指标合成总分。`score_summary.csv` 的 `total_score_by_n` 是按样本数加权的整体通过率，不能标作书籍七大类等权分或期刊任务等权分；工业 `quality_score` 是 0–100 的质量分，`hit` 才是 0–1 的合格率。旧服务器汇总报告曾混用这些列，使用时应以各运行的原始 CSV 为准。

现有第 5334 步模型的训练文件含飞机、书籍、期刊和园区评估内容，这四条链路的成绩不能作为独立泛化证据。工业数据并未进入那一轮训练，工业中文回退在全量同题对照中成立；检测测试媒体未发现与旧训练文件重合。后来过滤留出而重建的训练副本不改变已有模型的训练历史。

## 本轮代码输出

- 飞机仍按原验收口径出总分，新增 `aircraft_image_groups.csv`，按 `meta.source_dataset` 将飞机图与工业图分别报告，列出每个切片的评分行数和独立题数；该分组表不替代按既定权重计算的验收分。
- 工业主分数保持原口径，新增 `industrial_judge_errors.csv`，按正常/异常、缺陷桶、对象和来源列出裁判标记的漏检、误报、认错对象及认错缺陷类型。标记率不是独立检测器的召回率或误报率。候选评估数据的标签修订须经人工参考有效性复核后才能成为正式入口。
- 现有 `park_video` 结果称通用视频问答，不称异常识别。真正的异常事件评估需要经过双人核验的事件类别、描述与时段标注；类型命中、时间 tIoU、描述语义分别报告，不覆盖历史开放问答分数。
- 检测现有测试文件的 14,343 行缺少 `detect_box`、`count_class`、`inventory_locate`、`exist_negative` 任务。取消 300 行抽样仍不会产生这些切片。`tools/detection_coverage.py` 用于审计每个切片及其验收权重；补足缺口须另建有真实标注的评估题。

旧飞机评估集的完整 1,984 题按 `meta.source_dataset` 核对为飞机图 1,324 题、工业图 660 题。此前“工业图 350 题”只数了部分新增任务。现有 32B base / 第 5334 步结果按原五项各 0.2 权重回算：飞机图 **0.4138 / 0.8185**，工业图 **0.6183 / 0.8696**。对应五项有效评分行分别为 1,076 / 310；这张分组表只解释来源差异，不替代原整体验收分 0.4468 / 0.8226。

检测完整 14,343 条的只读审计显示，有标注的任务仅覆盖原验收权重的 **0.70 / 1.00**。多框检测占 0.20、计数占 0.10，两者当前均无题；清单与拒答也无题但在当前验收权重中为 0。另两个派生切片要在运行时生成，不能按原始数据行数宣称已有覆盖。

下一轮模型应在独立输出目录运行六条固定链路。工业中英各 500 题、园区通用开放问答 180 题已验证可全量运行。飞机、书籍、期刊可全量；检测先审计覆盖，再决定是否全量或按有标注的任务分层。新增正式评估数据前应完成真值复核和留出登记，历史报告不覆盖。

工业候选数据目前只有独立实验副本。人工复核队列覆盖 500 张配对图片，其中 128 张优先复核；每张图都要两名审核员给出参考有效性决定，分歧由第三人裁定。全部通过后发布脚本才会输出可评分的 `industrial` 数据及审计文件。现有复核决定栏全空，正式入口仍读取历史评估集。园区 NWPU 候选时段也尚未有人审类别与描述，不作为正式 `park` 异常分数。
