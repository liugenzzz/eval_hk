# 书籍评估：jsonl 直读 + 按七大类分别出分

书籍那批评估集每条自带一个领域分类（作战应用、拱形基础……七大类），报表要按这七类
分别出分。**没有任何书籍专属的代码** —— 用的是装备那条通路的 kind、提示词和报表维度，
区别全在配置。

---

## 一、评估集能直接读 jsonl 吗

能。真值文件按数据集名找，**优先 `<name>.jsonl`，没有再回落 `<name>.tsv`**。把
`book_vqa.jsonl` 放进 `tsv_dir` 就走评估集直读通路，不用先转 TSV。

认得的记录形状：

| 形状 | 处理方式 |
|---|---|
| `{"id", "conversations": [{"from": "human"/"gpt", "value"}], "images"}` | ShareGPT |
| `{"id", "messages": [{"role": "user"/"assistant", "content"}], "images"}` | OpenAI，书籍那批是这种 |
| `{"text": "...", "category": "..."}` | **跳过**，并打印跳过条数 |

`messages` 的 `content` 可以是字符串，也可以是 `[{"type": "text"...}, {"type": "image_url"...}]`
这种多模态数组，每个图片片段折算一个 `<image>` 标记，和 ShareGPT 的图片计数一致。
`system` 之类的角色会被丢掉 —— 既没问题也没参考答案，构不成可判分的一行。

`{"text": ...}` 只有正文，没有问题也没有参考答案，裁判无从打分，所以跳过。想评估这部分
内容，得先把它转成问答形式。整个文件都是这种行时会直接报错，不会静默出一张空报表。

多轮记录按轮次拆行，`index` 是 `<id>__t<轮次>`，**轮次从 1 开始**。

## 二、把分类放到打分维度上

数据集的 `params` 里指一下字段名：

```json
"datasets": {
  "book_vqa": {
    "name": "book_vqa",
    "kind": "judge_text",
    "params": {
      "category_field": "category",
      "default_category": "未分类",
      "image_root": "/评估机器上的/images"
    }
  }
}
```

- `category_field`：`category` 列取记录里的这个字段。先看记录顶层，再看 `metadata`，
  两处都没有或为空时落到 `default_category`。
- 不写这个参数时保持原样：`category` 列放 `metadata.task_type`（目标检测按任务拆报表
  就靠它），装备/目标检测两条通路一个字都不变。
- `image_root`：书籍记录带图时必配，不配的话 `image` 列是空的，推理和裁判都拿不到图
  （日志里会打「共 N 条中有 M 条无图」）。

## 三、出分

`report.dims` 里加一根 category 维度：

```json
"report": {
  "dims": [
    { "key": "category", "from": "category", "min_n": 10 }
  ]
}
```

```bash
cp book.example.json book.json      # 改路径
python -m eval_tool all --config book.json
```

`breakdown.csv` 里每个分类一行。`metric` 列区分口径，同一个分类会出多行：

| metric | 含义 | 量纲 |
|---|---|---|
| `quality_score` | **裁判 rubric 的原始分**，就是「作战应用 80 分」要的那个数 | 0-100 |
| `hit` | 通过率，`quality_score` 过没过阈值的比例 | 0-1 |
| `format_ok` / `task_bleed` 等 | 格式合规率、任务串味率 | 0-1 |

```
dataset   dim      value  metric         score   n  status
book_vqa  category 作战应用 quality_score   79.6  12  ok
book_vqa  category 拱形基础 quality_score   82.5  12  ok
book_vqa  category 作战应用 hit              0.70  12  ok
...
```

**两个口径别混着看**：通过率一样的两个分类，均分可以差十几分 —— 通过率只说「过了几条」，
均分说「答得多好」。要「作战应用 80」就看 `metric=quality_score` 那几行。

### status 与 min_n

每格带一个 `status`。`n` 少于维度的 `min_n`（默认 30）时是 `insufficient`：显示 `n`，
不显示百分比 —— 一个 n=3 的 100% 会被当成结论。七大类每类只有十几条时把 `min_n` 调到
10 上下，否则整张表都是灰的。五种 status 的完整含义见根目录 README 的报表文件一节。

### score_summary.csv 的那个总分

`score_summary.csv` 是另一套口径：按 `category_weights` 对各分类的**通过率**加权，出一个
`total_score`。它有自己的样本门槛，默认同样是 30 行，**行数不够的分类不进总分**，七大类
每类几十行以下时 `total_score` 会整列为空（各分类仍单独出列）。顶层加一个：

```json
"min_category_n": 10
```

调低这个门槛。它只影响 `score_summary.csv`，和 `report.dims` 里那个 `min_n` 互不相干。

想让某几类在总分里更重，写 `category_weights`；没列出的分类按 1.0 算。

## 四、一次评一串 checkpoint，和两两对比的开关

`models` 里想放几个放几个，`baseline_model` 指其中一个。评一串 checkpoint 时要注意
**成对比较的裁判开销是按模型数线性涨的**：

| | 裁判调用次数（R = 样本行数） |
|---|---|
| pointwise（每个模型各判一遍） | `N × R` |
| pairwise（每个挑战者 vs 基准，正反各判一次） | `(N-1) × R × 2` |

不是两两全配（全配是 `N(N-1)/2` 对），只有「每个 vs 基准」。但即便如此，N=7 时
pairwise 占掉总调用的 63%，比 pointwise 本身还贵。实测 7 模型 × 50 条：pointwise 350 次、
pairwise 600 次。

所以 `book.example.json` 里默认 **`"do_pairwise": false`**（目标检测那份出于同样的原因
也是关的）。关掉不影响本文要的东西 —— 每类 0-100 分走的是 pointwise，`breakdown.csv`
照常出。少的是 `pairwise_vs_baseline.csv`（胜/平/负率与区间）和成对的长度控制列。

只比 base 和一个 SFT 时，胜率比绝对分更灵敏，值得打开：

```json
"do_pairwise": true
```

打开后 `pairwise_vs_baseline.csv` 的 `scope=capability` 行本来就按 `category` 分组，
逐类胜率自动就有，不用另外配。

## 五、对其他通路的影响

| 改动 | 关掉时 |
|---|---|
| `params.category_field` | 不写就不生效，`category` 列仍是 `metadata.task_type` |
| `report.dims` 的 category 维 | 不写就不出这根维度 |
| `min_category_n` | 不写沿用原来的 30 行门槛 |

两处是纯增量、对所有通路都生效的：

- `messages` 形状的记录以前会让整份评估集报「select 没有选中任何样本」，现在能正常读；
  `conversations` 记录的解析一个字没变。
- `breakdown.csv` 和 `paired_diff_vs_baseline.csv` 多了 `quality_score` 这一档指标行，
  原有的行不变。

还修了一处：推理端读 jsonl 真值时不传数据集 `params`，`image_root` 因此静默失效，
推理拿到的是无图的行。现在推理和评估读的是同一批行。
