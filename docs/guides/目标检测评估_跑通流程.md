# 目标检测评估：怎么跑

**一条命令：**

```bash
cp det.example.json det.json      # 改路径，见下
python -m eval_tool all --config det.json
```

`all` = 推理 → 造派生集 → 再推理 → 评估 → 出报表。两个模型、十一个数据集，中间不用你插手。

口径和指标定义见 [../目标检测评估.md](../目标检测评估.md)，这份只讲怎么跑。

---

## 要改的只有四处

`det.example.json` 里，需要动的就这些：

```json
"tsv_dir": "/data/eval",                              ← test.jsonl 在哪
"dataset_defaults": {
  "image_root":          "/data/eval/images",
  "classes_yaml":        "/data/eval/classes.yaml",
  "labels_dir":          "/data/eval/labels",
  "describe_prompt_dir": "/data/builder/prompts/describe"
},
"models": [
  {"name": "base", "model_path": "/models/Qwen3-VL-8B-Instruct"},
  {"name": "sft",  "model_path": "/models/sft_ep2"}
],
"infer": {
  "training": {"image_min_pixels": 65536, "image_max_pixels": 589824}   ← 照抄训练配置
}
```

`dataset_defaults` 那四条路径写一次就铺给全部十一个数据集，不用逐个写。

`derive` 块（三个派生集怎么造）里的两个问法池路径也指到构建端：

```json
"derive": [
  {"dataset": "describe_modelhist",  "mode": "model-history", "sample_ratio": 0.3},
  {"dataset": "reverse_consistency", "mode": "reverse-consistency",
   "tasks": ["ground_appearance", "ground_full", "ground_relation"],
   "pools": {"region_identify": "/data/builder/prompts/region_identify/region_identify.txt"}},
  {"dataset": "question_perturbation", "mode": "question-perturbation",
   "variants": 3, "sample_ratio": 0.15,
   "pools": {"ground_appearance": "/data/builder/prompts/ground_attribute/ground_attribute.txt"}}
]
```

`source`（从哪份评估集派生）和 `from`（用谁的预测）能自动认出来，不用写 —— 前者取第一个非派生数据集，后者取唯一那个非基线模型。两个以上候选模型时会报错让你写明白，不会猜。

**开跑前值得花 10 秒确认一遍**（不用 GPU 不用裁判）：

```bash
python -c "
from eval_tool.config import load_pipeline_config
from eval_tool.run_eval import _scoring_plan
c = load_pipeline_config('det.json')
print('模型', [m.name for m in c.models], '数据集', len(c.enabled_datasets))
print('派生', [(p.dataset, p.mode, p.from_model) for p in c.derive_plans])
_scoring_plan(c.to_eval_config()); print('OK')"
```

路径写错、`kind` 拼错在这里就报，不会等你跑掉三小时推理才发现。

## 为什么是「推理 → derive → 推理」两趟

只有这一处不是一条直线，而且**没法压成一趟**：

```
① infer(八个主线)              模型答题
② derive                       拿①的输出造派生集（纯函数，秒出，不用 GPU）
③ infer(三个派生集)            模型对着自己的答案再答一遍
④ eval                         出报表
```

模型历史、双向一致性这两个指标的定义就是"拿模型自己的输出再问一遍"。模型还没答，就没有"模型自己的答案"可以拿来追问。`all` 会自动按这个顺序走，你不用管；知道这一点是为了看懂日志里为什么推理跑了两段。

## 跑完看什么

按这个顺序：

| 文件 | 回答 |
|---|---|
| `warnings.log` | **先看这个。** 有没有数据集被跳过、有没有图没读到 |
| `acceptance_score.csv` | 验收总分（只由代码打分器构成，不含裁判分） |
| `failure_buckets.csv` | 没达标的那部分，该往哪个方向补数据 |
| `paired_diff_vs_baseline.csv` | 相对 base 涨了多少，`significant` = 区间不含 0 |
| `breakdown.csv` | 哪一档 / 哪一类 / 哪种尺寸还不行 —— **这才是真正的产出** |
| `chain_decay.csv` | 瓶颈在定位还是在描述 |
| `judge_agreement.csv` / `judge_conclusion.csv` | 配了交叉裁判才有 |
| `run_fingerprint.json` | 这份结果评的是哪批样本、什么口径、哪个裁判 |

画框的验收口径：

```
达标 = 解析出框 ∧ IoU ≥ 0.5 ∧ 四点平均偏差/scale ≤ 5%
```

`failure_buckets.csv` 把不达标的拆成三个桶（加起来 = 1 − 达标率），各自对应不同的补数据方向：`malformed` 是训练配置问题、`localize_fail` 补指代消歧和密集场景、`deviation` 补精细边界（再看明细里的 `bias_*` 定方向，是系统性画小了还是画偏了）。

## 想省时间 / 跑挂了定位

一条命令跑不通的时候，按这几个开关缩小范围，而不是盯着几小时的日志翻：

| 想干什么 | 怎么做 |
|---|---|
| **先冒烟一下** | `"infer": {"limit": 20}` + `"enabled_datasets": ["ground_box", "region_identify"]`，几分钟出结果，**一次裁判都不调** |
| 只跑一个模型 | `--models sft`（会自动关掉 pairwise，不用改配置） |
| 裁判服务没起 | `"do_pointwise": false`，D 组只出三个代码指标（范围合规 / CHAIR 幻觉 / 空话），其余照常 |
| 跳过派生集 | `enabled_datasets` 里去掉后三个 |
| 只重出报表 | `python -m eval_tool eval --config det.json`，预测和裁判判词都在缓存里 |

**推理是断点续传的。** 中途挂了直接重跑同一条命令，已经推完的数据集会跳过。想强制重来才加 `--overwrite`。

## 六个坑

**① `classes_yaml` 不配，E 组主指标会偏高。** 兜底类别表只含评估集里出现过的 label。真值"人员"、模型答"军事人员"，最长匹配会从模型答案里抠出"人员"判成**完全正确** —— 白送分。配了会打印警告并把 `class_table_authoritative` 记成 0。同理 CHAIR 会**漏报**幻觉（模型编个"船"，表里没有"船"，那个词根本不会被认成类别）。

**② 像素面积必须和训练配置一致。** `infer.training` 写了就硬校验，不一致直接报错。分辨率变了，坐标虽是归一化的不会错位，但模型的空间精度会变，测出来的数字不可比 —— 而这件事**在报表上完全看不出来**，只表现为"这个 checkpoint 好像差一点"。

**③ `image_root` 没配对，整批预测都是废的。** `warnings.log` 里出现这条就立刻停：

```
[warn] ground_box 真值中有 N/N 行没有可用图片（image 列为空/NaN）
```

**④ 缓存不要删。** `cache_dir` 下的 `judge_cache_*.jsonl` 是重跑和加模型的全部本钱。缓存键第一位是裁判指纹，换 rubric、换裁判会自动 miss 重判，不会串。

**⑤ `baseline_model` 必须在 `models` 里。** 想只跑 sft 用 `--models sft`，别去 `models` 数组里删 base。

**⑥ 空格子不是 bug。** `breakdown.csv` 里 `status` 为 `by_design`（该组合本就不产样本）/ `not_in_data`（该任务产出为 0）/ `insufficient`（n < 30）时百分比都是空的。三种是完全不同的三件事，看到空格先看 `status` 那一列。

同理 `acceptance_score.csv` 在样本少的时候 `total_score` 会是空的、`excluded_small_n` 里写着 `ground_box(n=20)` —— 那是"n 不够不给结论"，不是算错了。
