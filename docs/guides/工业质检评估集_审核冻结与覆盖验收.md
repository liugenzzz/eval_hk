# 工业质检评估集：审核、冻结与覆盖验收

这条构建流程先扫描两份训练 JSONL，审核中英文映射和图片参考，再按明确配额构建一个固定评估集。正式推理、评分读取固定 JSONL，不再调用模型翻译或修改标签。工业评分仍用独立 `industrial_v1`，仅 pointwise。

源文件是实际训练格式：单张 `images`、一轮 `conversations`（human/gpt），答案开头为 `Category: …; Anomaly type: …; Description: …` 或 `类别：…；异常类型：…；描述：…`。原 `id`、分类元数据可缺失，构建器会补充；模型审核不会重写原问答。

## 一条命令构建

先安装项目依赖（配额求解需要 `scipy>=1.9`，YAML 使用 `PyYAML`）。在项目根目录执行：

```bash
pip install -r requirements.txt

python industrial_build.py \
  --zh /mnt/data3/code/trainspace/datasets/defect_vqa/merged_zh.jsonl \
  --en /mnt/data3/code/trainspace/datasets/defect_vqa/merged_en.jsonl \
  --out-dir data/industrial_quality \
  --zh-n 500 --en-n 500 \
  --object-min 10 --defect-min 3 --status-min 3 \
  --version industrial_labels_v1 --seed 42
```

这个命令会访问私有模型服务。样本质量审核按图片、问题和参考答案逐条进行；同图不同问答并不自动共享审核结果。大型训练集可能需要大量模型调用。可先按下面的分阶段流程扫描、查看规模，再审核。`--max-mapping-reviews N`、`--max-sample-reviews N` 限制本次调用条数，未审核项不会被当作通过；恢复时加 `--resume`，可提高或移除这两个预算。

示例要求每种语言：每个物体至少 10 条；每个「物体×缺陷类型」至少 3 条；该物体实际出现的正常/异常状态分别至少 3 条。默认三个最低配额均为 1，只保证覆盖存在性，不代表统计充分。需要稳定的逐类结论建议提高 `--object-min 30`；此时 500 条可能不够。构建器报告真实容量和最低预算，不会自动降低要求。

成功输出 `data/industrial_quality/evaluation/industrial_eval.jsonl`，共中文 500、英文 500 条。两种语言独立抽样，可能共享图片；每种语言内同一路径或相同图片文件内容最多一条。有 `metadata.workpiece_id` 时，同一来源域内同一工件最多一条；缺少工件 ID 无法保证去除同工件的不同拍摄角度，且图片 SHA256 去重不等同于近似图片去重。

模型不确定、参考冲突或配额不足时，命令非零退出并保留审计，不生成声称完整的评估集。网络错误可 `--resume` 重试；预算或最低配额改动应使用新输出目录。覆盖失败后新增审核结果再恢复，失败配额表会保留，新计划写入 `plan_attempt_2` 等目录。

## 私有模型配置

项目携带 `eval_tool/private_model_providers.json` 和私有服务路由器，服务器不需要本机 Codex skill 文件。此流程只配置两个 VLM 服务，不包含或检测 MinerU。默认服务与当前环境对齐：`qwen3.6-27b`（18180）和 `qwen3.6-27b_v2`（18181），二者后端 model 都叫 `qwen3.6-27b`。240 秒服务超时、最多两次自动尝试和 300 秒失败冷却保持不变。指定 `--provider` 时必须使用唯一 provider 名，并只调用该服务。

- `PRIVATE_MODEL_FX_Q3_235_API_KEY`
- `QWEN_36_27B_API_KEY`

凭据通过环境变量设置，不写进 YAML、审核结果或 Git。Windows 也支持读取用户持久环境变量。`PRIVATE_MODEL_ROUTER_CONFIG` 可指向服务器自己的同结构配置。

```bash
python -m eval_tool._private_model_router list
python -m eval_tool._private_model_router choose --task-type industrial_review --capability text
```

审核缓存保存服务名、模型名、结论和依据；接口错误只保存错误类型，不泄漏响应体或凭据。模拟测试验证接口、失败重试和缓存行为，不能代替服务器实际网络连通及真实样本的语义校准。

正式批量审核前，使用实际候选队列探测一条。它会验证 candidate SHA、请求接口和正式返回 schema，并对错误内容脱敏：

```bash
python scripts/probe_industrial_review.py \
  --build-dir data/industrial_quality_v2 \
  --provider qwen3.6-27b_v2
```

只有输出 `"ok": true`、`"schema_valid": true` 后再运行或恢复批量构建。短提示词返回 `{"status":"ok"}` 只能证明端口可用，不能证明模型服从工业审核 schema。

## 可分别运行的七个阶段

### 1. 全量扫描与候选映射

```bash
python industrial_mapping_build.py scan \
  --zh merged_zh.jsonl --en merged_en.jsonl \
  --out-dir build/scan --version industrial_labels_v1
```

逐行扫描，结构化前缀解析失败写进报告，不从长描述猜标签。候选映射以同图英文标签作证据，映射限定来源域、语言和物体上下文。同图互相冲突的标签记录为排除图片，不自动修复。

输出 `candidate.yaml`、`review_queue.jsonl`、`scan_report.json`。候选不是冻结文件，采样器拒绝直接使用。

### 2. 私有模型语义审核

```bash
python -m eval_tool.industrial_review mapping \
  --candidate build/scan/candidate.yaml \
  --queue build/scan/review_queue.jsonl \
  --out build/mapping_reviews.jsonl
```

所有中文标签映射（包括同图唯一对应）都会审核，英文中需要判断正常/异常等语义的标签也进入审核队列。按唯一映射规则审核，不逐条重复翻译。模型收到原标签、物体/来源上下文、同图候选依据，输出 accepted/rejected/uncertain 和理由。

有多个英文候选时只允许选择已有候选；没有候选时可以提出规范英文 ID，但必须明确接受且有语义依据。不确定不自动转为接受。模型建议可能仍有错误，审核结果和来源证据均保存供复核；不要求用户先提供原始 YAML。

### 3. 冻结真正的 YAML

```bash
python industrial_mapping_build.py freeze \
  --candidate build/scan/candidate.yaml \
  --reviews build/mapping_reviews.jsonl \
  --out-yaml build/industrial_labels.yaml
```

冻结文件包含版本、源 JSONL SHA256、显式物体与缺陷规则、正常/异常状态、模型审核依据、排除项。缺少审核、接口错误、冲突规则、候选之外的非法 ID 或物体/缺陷绑定冲突会阻止冻结。冻结后未知英文也不会自动新增标签。

拒绝/不确定项默认阻止冻结；只有明确使用 `--allow-partial` 才会冻结其余规则并记录排除项。**冻结部分映射不等于允许覆盖缺失**：采样时缺少的类别仍须列出并默认阻止通过。

### 4. 检查样本质量

```bash
python -m eval_tool.industrial_review samples \
  --zh merged_zh.jsonl --en merged_en.jsonl \
  --mapping build/industrial_labels.yaml \
  --out build/sample_reviews.jsonl
```

视觉模型看图片、原问题、原参考和冻结标签，检查问题可答性、对象、正常/异常、缺陷类型、外观位置是否一致，以及无依据的因果断言。输出 usable/conflict/insufficient；不读取被测模型预测、不改参考。构建代码另检查单轮单图、图片可解码、映射状态、重复和工件约束。

缓存绑定记录、语言、映射文件、提示词/服务配置及图片文件内容。图片变化必须重审；新审核失败不能沿用旧成功。API 错误记录为 error，恢复时会重试；模型明确给出的不确定结论保留为不通过。

默认不填图片根目录：构建审核和抽样使用源 JSONL 的 `images`；绝对路径直接使用，相对路径按源 JSONL 所在目录解析。输出到新目录时，相对图片路径会转成已核验的绝对路径，原值保存在 metadata，避免移动评估文件后路径失效。

原绝对图片路径在新服务器不可用时，可在**构建命令**传 `--image-root /new/defect-detect-images`，按识别出的来源域相对路径查图。审核、计划和采样必须使用同一参数。采样会把输出图片路径改为实际位置，并在 metadata 保留原图片字段。

### 5. 先出覆盖统计与配额计划

```bash
python -m eval_tool.industrial_quality_sample \
  --zh merged_zh.jsonl --en merged_en.jsonl \
  --mapping build/industrial_labels.yaml \
  --quality-review build/sample_reviews.jsonl \
  --out-dir build/plan --plan-only \
  --zh-n 500 --en-n 500 --object-min 10 --defect-min 3 --status-min 3 --seed 42
```

生成 `coverage_plan.csv/json`、`coverage_report.json`、`quality_audit.jsonl` 和 manifest，不产评估集。物体、物体×缺陷、物体×正常/异常都是硬配额；来源域用于分布展示及余量平衡。整数约束求解器同时检查去重/工件限制和最低配额，报告最低可行预算。求解超时属于未证明可行，会留下原因，不能当作通过。

每个单元格显示 `available`、`minimum`、`planned`、`selected`、`gap`、`reason`。映射失败的原始类别和质量检查后容量为零的类别仍在表里，不静默消失。预算不足、某类没有合格样本、来源记录无法分类都会明确阻止验收。

若预算不足，基于表中的 `minimum_budget` 增加样本量，或建立显式排除的长尾专项集；合并类别必须重新审核并升级映射版本，不能在本次抽样中临时改。`--allow-partial-coverage` 是显式降级开关，允许放弃无可用样本的类别，但仍展示缺口并记录参数；默认关闭。

`--quality-mode structural` 可用于不调用模型的格式联调，但报告会明确标记 structural，不可宣称完成了视觉参考审核。正常正式构建使用默认 semantic，并要求有效的审核文件。

### 6. 按冻结计划抽样

```bash
python -m eval_tool.industrial_quality_sample \
  --zh merged_zh.jsonl --en merged_en.jsonl \
  --mapping build/industrial_labels.yaml \
  --quality-review build/sample_reviews.jsonl \
  --plan build/plan/coverage_plan.json --out-dir build/evaluation \
  --zh-n 500 --en-n 500 --object-min 10 --defect-min 3 --status-min 3 --seed 42
```

输入、映射、审核、参数和图片哈希必须与计划一致。成功才发布单个 `industrial_eval.jsonl`，补充唯一 ID、language、canonical 物体/缺陷、defect_status、版本哈希和来源信息。原问题与答案不改写。

### 7. 验收冻结产物并评估

```bash
python -m eval_tool.industrial_frozen_check --dataset build/evaluation/industrial_eval.jsonl
```

验收核对 JSONL 哈希、ID、实际图片哈希。JSONL 与同目录的 `manifest.json` 一起保留。使用新增 `industrial_quality.example.json`（复制为 `industrial_quality.json`），填模型路径/GPU/裁判地址；若按分阶段命令构建，将 `tsv_dir` 改成 `build/evaluation`。

```bash
python -m eval_tool infer --config industrial_quality.json
python -m eval_tool eval --config industrial_quality.json
```

新配置开启 `dataset_defaults.verify_frozen_manifest`，在推理和评分前复核冻结数据和图片，变化即报错。只对显式开启此检查的数据集生效，书籍、装备、检测与旧工业配置不变。

评估配置的 `image_root` 也默认省略，加载器直接使用评估 JSONL 的 `images`；其中的相对路径按评估 JSONL 所在目录解析。显式填写 `image_root` 只改变相对路径的基准，不替换记录中已有的绝对路径；它与构建命令的迁移重定位选项作用不同。

不再运行 mapping/sample review。被测模型看图答题，工业裁判 `industrial_v1` 逐条评分，中英文切片不重叠，报表按语言、物体类型输出维度分和有效性统计。两个阶段的模型职责不同：构建模型检查数据，评估裁判检查被测回答。

## 结果如何解释

通过构建验收表示满足所设配额、去重、冻结和审核门槛，不代表模型审核必然正确或每类样本数充分。仍须关注审核冲突率、缺失类别和每类有效 n。构建来源是训练文件，manifest 明确标记 `training_regression`；高质量筛选也不能把训练集成绩变成独立泛化成绩。

旧 `extract_industrial_eval.py` / `industrial_mixed.example.json` 保留为基础抽样流程。旧 `industrial_mapping_build.py --en ... --mapping-yaml ...` 仅生成候选文件；完整流程应使用上述 scan/review/freeze/quality/plan/sample 阶段或总入口。
