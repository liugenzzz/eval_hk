# 工业质检描述评估

以**物体类型**为主分类，中文、英文分别报告描述质量。使用独立 kind `industrial_describe`、工业裁判提示词 `prompts/judge_industrial_pointwise_v1.txt` 和 rubric `industrial_v1`，复用推理输入与 pointwise 基础设施，不运行 pairwise。独立配置为根目录 `industrial.example.json`，内置 profile 为 `industrial_bilingual_v1`。装备、书籍原提示词保持不变。

## 当前数据检查

检查路径：`F:/AI-Haishi/智航院/dataset/defect-detect-data/defect-detect-main`（2026-09-15）。

- 各域顶层共 25 个 CSV，322,904 条记录、565 个标签/类别组合；不是 565 个物体类型。
- 字段主要是 `Image Name`、`label/Label`、`Categories/categories`、`Description`；MVTec 的描述列叫 `Diversified Description`。混凝土 CSV 需要 `gb18030` 解码。
- 内容是物体、缺陷及其描述，部分混有成因、影响和通用知识；不是统一的检测框标注，也不是已经整理好的问答 JSONL。
- 数据量很不均衡：ICCAD 非热点 160,963 条、TIG 45,058 条、半导体 34,116 条、混凝土 31,688 条。直接全局随机抽样会偏向大域。
- 当前有 127,627 张已解压图片，另有 24 个 ZIP；不能仅凭 CSV 行数认定图片全部就绪。

参考答案存在冲突。例如 `oled22_normal_001.jpg` 标为 `OLED,good`，描述先称无缺陷，随后又谈边缘缺陷；`mt3_free_001.jpg` 的正常类参考主要列举常见缺陷。白酒 `bottle,label wrinkle` 的部分参考却描述瓶盖划痕；solarcrack 的 `scratch` 标签与 microcracks 描述也不一致。

因此保留原始类别、label 和描述，冲突样本经人工核对后再纳入正式评测。不能根据 Description 出现 crack/normal 等关键词就生成可靠的缺陷真值。模板重复很多，也不能仅按文本去重：同一描述可能对应不同图片。

用户说明这些是真实训练数据；本目录用于适配数据格式和核查口径。若直接抽取，结果应标为训练集回归成绩。泛化测试需先按原图/工件/来源组隔离训练集，再抽样；译文与原文属于同一个样本组。

## 怎么分维度

主报表是「模型 × 语言 × 物体类型」。物体类型采用稳定的、两种语言共用的类别编码，如 `aircraft_skin`、`bottle`、`cable`；显示名称可以翻译，但分组编码不翻译。MVTec、VisA 是来源域，不能直接代替物体类型。

| 字段（位于 metadata） | 用途 | 是否必须 |
|---|---|---|
| `object_category` | 物体类型，主分组及抽样第一层 | 配对抽样必须 |
| `source_domain` | 来源数据域，辅助检查覆盖 | 建议保留 |
| `defect_type` | 缺陷类型，物体内部抽样及辅助报表 | 可选 |
| `defect_form` | 裂纹形态、斑点形态等 | 有可靠标注才填 |
| `defect_location` | 缺陷位置 | 有可靠标注才填 |
| `defect_status` | 正常/异常 | 核对过才填 |
| `raw_categories`、`raw_label` | 原始标注溯源 | 建议保留 |

类别字符串不一定只是两个元素。例如 `solar cell,monocrystalline,crack` 含材料子类；`aluminum,marker stain,pin hole` 含多种缺陷。不要直接把第二段当作唯一缺陷；多缺陷可使用人工约定的稳定组合编码，当前报表不会自动展开多标签。

初版无需另建一套全属性真值。缺陷形式、位置未标注时留缺失，不能补成“正确”或 100 分。按 `defect_type=crack` 分组得到的是**这类样本的描述得分**，不是单独的裂纹识别准确率。

## 独立工业评分口径 industrial_v1

物体类型是**统计分组**；下面四项是每条回答的**评分维度**。二者分别回答「在哪类物体上表现如何」和「具体哪种能力有问题」，不能互相替代。装备 v4 的军事装备认定、事实和参数口径不适合直接作为工业质检指标，因此本通路使用单独版本。

| 评分字段 | 评价内容 | 初始权重 |
|---|---|---|
| `object_score` | 物体/工件类别是否正确 | 20% |
| `defect_score` | 正常/异常判断和缺陷类型是否正确，是否漏报或误报 | 45% |
| `appearance_score` | 可见缺陷的形状、纹理、颜色等外观是否描述准确 | 20% |
| `location_score` | 缺陷所在部位、相对位置是否准确 | 15% |

各项为 0–100 分。不适用或缺少可靠证据的非核心维度记 `null`，只对适用项重新归一权重，不能按 0 或 100 补齐。正常样本不强制描述不存在的缺陷外观、位置。数量标注不充分，初版不单列计数维度。

准确性加权分再乘无编造系数 `0.5 + 0.5 * fabrication_score / 100`；`fabrication_score` 越高表示越少编造。表达质量 `style_score` 留作诊断，不进入总分。`critical_errors` 中出现 `wrong_object`（物体认错）、`missed_defect`（漏报缺陷）、`false_alarm`（正常误报异常）或 `wrong_defect_type`（缺陷类型认错），总分最高为 30 分；最终总分达到 60 分才通过。

若裁判看到的参考答案与图片在核心判断上冲突，或证据不足以判断核心内容，分别记 `reference_status=conflict` / `insufficient`，保留原因并从有效得分、通过率分母剔除，**不记为模型 0 分**。这些样本需人工复核后再用于正式结论。裁判输入不包含原始 metadata 标签，因此 CSV 标签与描述的冲突仍需在输入前人工核查，不能依赖裁判自动发现。

以上权重、封顶和阈值是工程初始口径，尚未经过真实裁判与人工标注校准。正式运行前应抽查不同物体的正常、异常样本，核查漏报、误报和判词。各维度均分是裁判评价，不是严格的物体分类准确率、缺陷识别 accuracy 或检测指标；后者需要可靠结构化真值与独立计算。

成因、影响、维修建议通常无法单凭图片确认，不宜强制要求模型复述。训练使用的中英文术语表应同时用于两份参考答案；不会因为中英文措辞不同就把同义答案当成错误。

## 中英文各 1000 条

推荐同一组 1000 个图片问答分别使用中英文版本，共 2000 条评测回答。这样物体类型、缺陷、图片难度配对一致。若两种语言各抽不同图片，只能比较各自成绩，不能把分差全部归因于语言能力。

独立工具 `eval_tool.industrial_sample` 接受已整理好的中英文 JSON/JSONL；不调用模型，不翻译，不直接拿原始 CSV 当问答。先等额覆盖物体类型，再在物体内部轮转来源域/缺陷层；不足的层把剩余配额交给其他层。固定 seed、配对 ID 和源文件哈希写入 manifest。

每条应是一轮问答，例如下面是**字段示意，不是已核验的正式参考答案**：

```json
{
  "id": "aircraft_skin_0001",
  "images": ["0-4aircraft4000/0to4_aircraft_skin4000pics/1_aircraft_skin4000pics/crack/aircraft1_crack_001.jpg"],
  "messages": [
    {"role": "user", "content": "<image>请描述图中的物体及可见缺陷。"},
    {"role": "assistant", "content": "此处填写经核对的中文参考描述。"}
  ],
  "metadata": {
    "pair_id": "aircraft_skin_0001",
    "object_category": "aircraft_skin",
    "source_domain": "0-4aircraft4000",
    "defect_type": "crack",
    "raw_label": "0",
    "raw_categories": "aircraft,crack"
  }
}
```

英文记录用对应英文问题/答案，保留相同图片、`pair_id` 和分类编码。没有 `metadata.pair_id` 时用顶层 `id` 配对。不要把答案里的缺陷提示塞进被测问题，使用实际评估任务的问法。单个 `Image Name` 一般不足以定位图片，需要映射成相对 `image_root` 的真实路径。

```bash
python -m eval_tool.industrial_sample --zh /data/heldout_zh.jsonl --en /data/heldout_en.jsonl --out-dir data/industrial --sample-n 1000 --seed 42
```

工具输出 `industrial_zh.jsonl`、`industrial_en.jsonl`、`manifest.json`。输出顶层 `id` 统一为配对 ID，原 ID 不同时保留到 `metadata.original_id`。缺失/重复配对 ID、两种语言 ID 集合不同、问答为空、多轮、配对类别或图片路径列表不一致会报错。图片路径不能为空；问题中 `<image>` 标记数量只能为零（加载器使用全部图片）或图片总数，避免中英文实际使用不同的图片子集。不足 1000 对也会报错，不重复采样凑数。已有产物不覆盖。工具不核验翻译语义、不检查训练重叠，不替代人工标注复核和图片文件可用性检查。

1000 条不足以让几百个细分类都达到可靠样本量；以较粗的物体类型为主是合理的。每类建议至少 30 对，30 以下默认在细分报表标 `insufficient`；不要为了每格都有分数而随意降低门槛。

## 运行

复制 `industrial.example.json` 后填实际 checkpoint，按执行机器调整 `image_root`、GPU 和既有裁判服务。示例模型路径仅为占位。数据目录放上述两个 JSONL；不要设置统一 `eval_set`（它会把两种语言文件重命名到同一个来源），也不要再设置单语言 `sample_n` 二次抽样。

```bash
python -m eval_tool infer --config industrial.json
python -m eval_tool eval --config industrial.json
```

profile 已配置独立工业 rubric，并关闭 `do_pairwise` 和 `do_length_control`。推理、报告、裁判缓存均位于 `eval_output/industrial/industrial_v1/`；原有三个通路的配置与 prompt 无需改动。也可显式传 `--rubric industrial_v1`，但该 CLI 方式会在报表目录名追加 `_industrial_v1`，下面的离线汇总路径需要相应调整。

## 看哪些结果

- `breakdown.csv`：按数据集区分中英文，`dim=object_category` 是主分类。`metric=quality_score` 是 0–100 描述均分，`metric=hit` 是通过率。`n` 为有效得分样本数，裁判失败不会算成 0 分。
- `judge_detail_all.xlsx`：逐条答案、判词、工业各维分数、参考有效性状态及关键错误，供错误分析。参考冲突/证据不足与裁判失败都应核查其原因，不按模型答错计数。
- `industrial_quality_scores.csv`：自动输出工业各评分维度的汇总，分别检查中英文及物体类型的能力短板。
- `industrial_judge_status.csv`：自动输出有效、参考冲突、证据不足和裁判失败计数，用于检查有效样本覆盖。
- `score_summary.csv`：沿用现有按 category 汇总的通过率口径，可能跨语言合并，**不要当作中英文各自的描述均分**。这里也没有用目标检测的代码验收总分替代裁判评分。

如果要把物体、缺陷、外观、位置、无编造等分数也按物体类型列成表，运行离线汇总命令，不会再次调用裁判：

```bash
python -m eval_tool.industrial_report --details eval_output/industrial/industrial_v1/eval_report/judge_detail_all.xlsx --out eval_output/industrial/industrial_v1/eval_report/industrial_scores.csv
```

`industrial_scores.csv` 按语言数据集分别输出 overall、object_category 的均分、有效 n 和区间。共享的 `judge_detail_all.xlsx` 保留工业分维与状态字段；缺少额外 metadata 时，工具用其中的 `category` 恢复物体分类。若还要来源/缺陷等辅助维度，用 `--details detail_base_industrial_zh.xlsx detail_base_industrial_en.xlsx` 传入每模型每数据集的完整明细（填实际路径；可继续列出其他模型的明细）。不要把总明细与其子文件一起输入，否则会重复计数并报错。

例如 `location_score=null` 不会变成 100 或 0；某维全不适用时不出虚假的均分行。参考无效样本不进入各项有效均分，需结合明细核查被剔除的数量与原因。默认只读取 `industrial_zh`、`industrial_en`，不改变书籍/装备/检测报告。自定义数据集键名时用 `--datasets key_zh key_en`。

建议主表展示每类物体得分、样本数和各语言总体均分，同时检查小类覆盖；物体配额改变后应重新冻结评估集版本，避免把样本分布变化误认为模型提升。
